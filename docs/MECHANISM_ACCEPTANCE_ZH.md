# 面向 design 的模拟器验收：外部依据与机制证据

当前结论：**可用于有明确假设的功能/机制探索；尚不能作为已校准的 HBF 性能预测器。**
上一轮 64 点完成和 56 点逐字回归只证明执行优化没有改变那些结果，不能证明结果符合真实 HBF。

## 外部来源必须分层

| 来源 | 能用于验收的内容 | 证据边界 |
|---|---|---|
| [OCP HBF v0.7.0](https://www.opencompute.org/documents/ocp-hbf-architecture-specification-v0-7-0-final-pdf/)，§5.3.1、§5.3.2、§5.4.1、CSR NCBB | 64 B 读粒度、同 bank sense 顺序、至少两个页缓冲、读命中/错误处理、写响应与媒体提交关系 | 不提供 NAND sense 实测时延；不是一条可直接拟合的产品吞吐曲线 |
| [Characterizing and Exploiting Dense Retrieval on HBF](https://research.ece.cornell.edu/retrieve/camera-ready/retrieve26-final50.pdf)，§IV-C、Table II、Fig.3(b) | 同页复用、不同 bank 并行、同 bank 串行、独立/依赖请求及页效率；512 GiB、16×4×16、4 KiB、双缓冲 | 2.72 μs 是为吞吐一致性选取的 nominal 输入；不能用该拟合条件再次充当独立验证集 |
| [HAVEN](https://arxiv.org/html/2603.01175v1)，§3.2、§4.1 | 8-Hi、460 GB/s 上限、30 W 包级约束；有限 rerank queues/MAC/sorter 的设计结构 | 是不同的建模配置。不能把功耗受限带宽和 OCP SG2 混成同一设备；目前没有复现其完整近存计算链路 |

外部数值冲突保持显式：现有 SG2 section 参数 94×16=1504 GB/s，与 OCP Table 4/检索论文的 1536 GB/s 分列。不能为了曲线接近而偷偷替换。

## 本轮新做的机制验收

新探针走真实 HostDriver → DeviceDriver → NAND/cache/Core Channel → response 路径，先正常写入，再正常读取；不直接修改私有设备状态。Python 参考端不导入 EventLab。

| 测试 | 独立判据 | 分类 |
|---|---|---|
| 双缓冲与冲突 | FIFO/LRU 共 524 个顺序阶段，含 A/B/A/C/A/B 和固定种子访问；逐步比较实际 sense 次数与两槽参考机 | 双缓冲有 OCP 依据；默认 FIFO 对应第三页淘汰第一页示例，LRU 为显式敏感性选项 |
| 同页在途请求 | 两个同页请求只激活一次 | 检索论文机制；不是所有调度条件下无条件合并 |
| 同 bank / 不同 bank | 同 bank 操作区间不重叠；独立 bank 定向案例必须重叠 | 规范顺序约束＋当前模型并行能力 |
| 媒体时延因果性 | 单个冷 miss 改变 sense 参数时，端到端时间变化恰等于参数变化；热 hit 不受影响 | 参数传播检查，不是外部时延校准 |
| 有限 Core Channel | 8/16 B/ns 两档；每次 4096 B 传输满足独立 FIFO 保留区间、无重叠、完成因果性 | 有限资源/当前 FIFO 假设，不是 OCP 要求的速率 |
| 负向测试 | 篡改 sense 次数、媒体完成时间、通道区间和总完成时间均被拒绝 | 检查器敏感性 |
| 生产实现变异 | 单槽缓存、错误地在 FIFO 下更新命中 recency，分别编译运行并要求参考端拒绝 | 分别覆盖容量约束与替换假设；不能混称规范违规 |

原来的 `sense-finish` 实际在 Core 传输后触发，代表缓冲可见/释放 bank 的时刻。本轮增加 `sense-media-finish`，使媒体完成、通道排队、数据可见分别可观测；不改变事件时间或资源行为。否则会把通道排队误认为 NAND 变慢。

这些测试仍不覆盖任意并发缓存淘汰、所有协议字段、所有故障交错。既有 reset/retry/ID 复用测试应继续保留，不被这组微测试替代。

## 必须保留的阻断项

1. **缓存默认策略已修复，完整符合性仍未证明。** 默认按填入顺序选择最老的可淘汰槽，命中不更新次序；`execution.cache_hit_recency=true` 才使用旧 LRU，配置摘要会记录此选项。对应 OCP §5.3.1(7) 的第三页淘汰第一页示例；不能从一个示例推出所有并发场景的规范算法。被引用或正在填充的槽仍不可淘汰。A/B/A/C/A/B 及固定种子独立差分已验证两种策略，任意并发淘汰仍需进一步覆盖。
2. **冷吞吐尚未对齐。** 当前冻结有限批次中，冷 4 KiB、顺序独立 QD1024 为 115.756 GB/s；论文讨论全利用条件接近 SG2。由于命令拆分、入口容量、提交/完成边界和稳态条件尚未逐项相同，这不是可宣称的“13 倍预测误差”，但确实没有完成对齐。新增配对诊断已确认原 MOCS256 的活跃 bank 峰值只有 80；QD128 下仅扩大 MOCS 到 4096，峰值升至 128，模型吞吐从 115.756 升至 185.739 GB/s。命令供给限制已获证据，仍需补齐稳态、全利用以及外部匹配条件；见缓存修复报告。
3. **有限 Core 的 bank 占用。** 当前 bank 直到 Core 传输完成才释放。这是可检验的模型行为，不是已经证明的产品流水线；需要明确设备能否在传输期间启动下一次 sense。
4. **缺少外部留出曲线。** 论文未提供的 trace、QD、计时边界和数值曲线仍是缺口。近似数字化图线须保留误差范围；不同工况的数值不能凑成“验证集”。
5. **HAVEN 设计域未验收。** 候选 trace、near-storage distance/top-k 结果、有限队列/MAC/sorter、HBM 并发和功耗受限供给必须形成同一闭环。A6000 只能验证 CUDA 功能，不能验证 HBM/HBF 时序。

## 何时可以据此提出 design 结论

- 协议与状态机：按条款覆盖正常、竞争、恢复；不变量违规为零，不能用数值误差容忍协议错误。
- 资源与因果：每个候选设计的瓶颈都能用可观测事件解释；关闭/增大某项资源的反事实结果符合独立预期。
- 外部曲线：拓扑、地址映射、缓存、命令粒度、到达方式、计时区间完全匹配；报告全曲线残差、饱和拐点和尾部，而非挑一个点。
- 拟合与验证：先固定参数来源和拟合集；不同 seed、地址冲突、QD、依赖模式和缓存状态留出。误差容限依据参考数据不确定性及待证明的设计效果预先确定，不能看结果后移动。
- 设计稳健性：在有证据支持的参数区间和所有仍合法的模型解释下，与同语义、同资源强基线比较。若合理的 FIFO/LRU、bank/Core 流水线或 sense 参数变化会反转优劣，报告条件性结论，不能宣称设计获益已确认。
